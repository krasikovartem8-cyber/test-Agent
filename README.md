# Browser Agent — автономный AI-агент для браузера

Агент получает текстовую задачу в терминале, открывает настоящий браузер и решает её сам: изучает страницу, нажимает кнопки, вводит текст, читает результаты, а в конце отчитывается. Никаких заранее заданных планов, селекторов или подсказок по конкретным сайтам в коде нет — агент каждый шаг определяет из того, что видит на странице.

```
👤 You: открой яндекс лавку, выбери мой рабочий адрес, найди хот-дог и добавь его в корзину, не оплачивай

🤖 Assistant: Открываю Яндекс Лавку.
🔧 Using tool: navigate
   Input: { "url": "https://lavka.yandex.ru" }
   Result: Navigated to https://lavka.yandex.ru (title: "Купить продукты с доставкой…")

🔧 Using tool: get_page_state
   Result: URL: https://lavka.yandex.ru
           Interactive elements in viewport (48):
             [1] <button> "Москва, ул. …"
             [2] <input:search> placeholder="Найти в Лавке"
             …
🔧 Using tool: query_page
   Input: { "question": "Какие хот-доги есть в результатах и где кнопки добавления в корзину?" }
🔍 DOM sub-agent: Хот-дог Датский Грабли Box 135 г — 279 ₽, кнопка «+» [57]; …
🔧 Using tool: click
   Input: { "ref": 57 }
…
✅ SUCCESS
Выбран адрес «Работа», найден «Хот-дог Датский» (279 ₽), добавлен в корзину (1 шт.). Итог в корзине 388 ₽. Оплату не производил.
```

## Стек и ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Язык | TypeScript (Node ≥ 20) | Лучшие SDK и для Playwright, и для Anthropic; один процесс — браузер и агент |
| Автоматизация браузера | **Playwright** (persistent context, канал Chrome) | Стабильные действия с авто-ожиданием, пробивает Shadow DOM, persistent-профиль сохраняет логины между запусками, встроенная запись видео |
| Модель | **Claude Opus 5** (`claude-opus-5`) через `@anthropic-ai/sdk`, ручной агентный цикл с tool use | Ручной цикл (а не Tool Runner) даёт полный контроль над историей, компакцией, стримингом и retry |
| Субагент | Claude Sonnet 5 (`claude-sonnet-5`) | Чтение больших страниц и сжатие истории — дешевле и быстрее |
| Представление страницы | Собственный DOM-снапшот с нумерованными элементами `[N]` + опциональный скриншот | См. раздел «Как агент видит страницу» |

## Архитектура

```
src/
  index.ts              CLI: терминальный REPL, запуск браузера, команды /reset /tabs /exit
  config.ts             настройки из .env
  agent/
    Agent.ts            автономный цикл: модель → инструменты → результаты → … → finish
    tools.ts            описания инструментов (JSON Schema) — универсальные, без привязки к сайтам
    prompts.ts          системный промпт, промпт субагента, промпт компакции
    context.ts          управление контекстом: учёт токенов, компакция, заметки, детектор зацикливания
    subagent.ts         DOM-субагент (query_page)
  browser/
    Browser.ts          обёртка над Playwright: навигация, клик/ввод/скролл по ref, вкладки, диалоги
    snapshot.ts         сбор снапшота внутри страницы и его текстовое представление
  ui/
    terminal.ts         вывод в терминал: стрим текста и рассуждений, вызовы инструментов, вопросы пользователю
scripts/
  smoke-browser.ts      снапшот любой страницы без API-ключа
  mock-run.ts           прогон агентного цикла со скриптованной «моделью» (без API-ключа)
```

### Цикл агента

1. Модель получает системный промпт, список инструментов и историю; ответ стримится в терминал (текст и краткие рассуждения).
2. Все `tool_use` из ответа исполняются, результаты возвращаются одним `user`-сообщением (в том числе ошибки — с `is_error`, чтобы агент сам исправился).
3. Повтор, пока модель не вызовет `finish`, не задаст вопрос через `ask_user`, или не исчерпает лимит шагов (тогда пользователя спрашивают, продолжать ли).
4. Прозрачные API-ошибки (429, 5xx, сеть) — повтор с задержкой; `refusal` и `max_tokens` обрабатываются явно.

### Инструменты

`navigate`, `get_page_state`, `screenshot`, `click`, `click_at`, `type_text`, `press_key`, `scroll`, `select_option`, `hover`, `wait`, `go_back`, `list_tabs`, `switch_tab`, `get_page_text`, `query_page`, `remember`, `ask_user`, `finish`.

Все они универсальные. Единственный «адрес» элемента — его номер в последнем снапшоте. Агент сам решает, что такое «кнопка добавления в корзину» на конкретном сайте.

### Как агент видит страницу

Рассматривались три подхода:

- **Только скриншоты** (computer-use). Просто, но дорого по токенам, неточно для мелких элементов и плохо для чтения длинных списков.
- **Accessibility tree** Playwright/CDP. Хороший источник имён, но на реальных сайтах (Лавка, hh.ru, почта) дерево огромное и шумное, а многие кликабельные `div`-ы в нём не помечены.
- **Собственный DOM-снапшот** — выбран. Скрипт выполняется внутри страницы (`snapshot.ts`): обходит DOM включая открытые Shadow DOM, отбирает *видимые* интерактивные элементы (ссылки, кнопки, поля, элементы с ARIA-ролями, `onclick`, `tabindex`, contenteditable), вычисляет доступное имя (aria-label, label, текст, placeholder, alt), помечает каждый атрибутом `data-ba-ref="N"` и возвращает компактный список:

  ```
  [12] <button> "В корзину"
  [13] <input:search> placeholder="Найти в Лавке" value=""
  [14] <a> "Хот-дог Датский" href=/product/…
  ```

  Элементы во viewport идут первыми, остальные — отдельным блоком с подсказкой «проскролль». Плюс начало видимого текста страницы и позиция скролла. Скриншот подключается по запросу агента (`include_screenshot`/`screenshot`) — для модальных окон, карт и неочевидных состояний.

Действия выполняются через `locator('[data-ba-ref="N"]')`; если после действия страница поменялась и элемент исчез, агент получает понятную ошибку с инструкцией обновить снапшот. Клик пробует обычный Playwright-клик, при перекрытии — DOM-событие; ввод — `fill()`, при отказе — реальные нажатия клавиш. Новые вкладки и диалоги (`alert`/`confirm`) перехватываются и сообщаются агенту.

### Управление контекстом

Длинные задачи (десятки шагов, каждый со снапшотом) быстро раздувают контекст. Что сделано:

1. **Экономия на источнике.** Снапшот ограничен по числу элементов и объёму текста; `get_page_text` читает страницу порциями; полный текст страницы в основной контекст никогда не попадает.
2. **Делегирование чтения субагенту** (`query_page`). Полный текст страницы и *все* интерактивные элементы уходят Sonnet 5 отдельным запросом; в основной контекст возвращается только короткий ответ с нужными ref. Документ страницы помечен `cache_control`, так что повторные вопросы к той же странице попадают в кэш.
3. **Учёт размера контекста** по `usage` каждого ответа (input + cache + output).
4. **Компакция.** При превышении `CONTEXT_TOKEN_LIMIT` вся история переводится в текстовый транскрипт, Sonnet 5 пишет плотную сводку (что сделано, факты, что осталось, какие элементы оказались нужными), и диалог начинается заново с одного сообщения: задача + сводка + заметки + «браузер открыт на URL, начни с get_page_state».
5. **Заметки вне истории** (`remember`). Факты, которые нельзя потерять (цены, ID, выбранные варианты), хранятся отдельно и вставляются после каждой компакции.
6. **История append-only между компакциями.** Исследование API показало: у современных моделей Claude блоки рассуждений привязаны к точному префиксу диалога, и редактирование старых сообщений (популярный приём «вырезать старые снапшоты») их инвалидирует; для новых аккаунтов это уже ошибка 400. Поэтому вместо переписывания истории используется рекомендованная Anthropic схема «simple compaction» (сводка + новая история), а объём наблюдений ограничивается заранее.
7. **Prompt caching**: системный промпт и список инструментов стабильны и помечены `cache_control`, поэтому большая часть каждого запроса читается из кэша.

### Продвинутые паттерны

- **Субагент для DOM** (`query_page`) — разделение «действующего» и «читающего» контекстов, разные модели под разные роли.
- **Компакция с внешней памятью** — сводка + `remember`-заметки.
- **Детектор зацикливания** — три одинаковых действия подряд → агенту добавляется указание сменить стратегию.
- **Human-in-the-loop** — `ask_user` останавливает агента только когда нужны данные от человека (логин, 2FA, подтверждение необратимого действия); лимит шагов тоже требует подтверждения.
- **Самопроверка перед finish** — промпт требует наблюдать результат после каждого действия и подтверждать выполнение (URL, счётчики, сообщения) до отчёта.

## Запуск

Требования: Node.js ≥ 20, Google Chrome (иначе будет скачан Chromium), ключ Anthropic API.

```bash
git clone <repo> browser-agent && cd browser-agent
npm run setup            # npm install + playwright install chromium (запасной браузер)
cp .env.example .env     # вписать ANTHROPIC_API_KEY
npm run dev
```

Дальше в терминале пишете задачу и наблюдаете за браузером. Задачу можно передать и аргументом:

```bash
npm run dev -- --task "Найди на hh.ru вакансии Python-разработчика в Москве с зарплатой от 200 тысяч и выпиши три самые интересные"
```

Флаги: `--record` — писать видео браузера в `./recordings`; `--headless` — без окна. Команды в REPL: `/reset` (забыть историю), `/tabs`, `/exit`. История между задачами сохраняется, так что можно давать уточнения: «теперь добавь ещё один».

Профиль браузера лежит в `.browser-profile` — залогиньтесь один раз в нужных сервисах (почта, магазины), и агент будет работать под вашими сессиями. Пароли агент сам не вводит, если вы их не дали явно, и останавливается перед оплатой, если задача её не разрешала.

### Проверка без ключа

```bash
npm run smoke -- https://ru.wikipedia.org   # что агент «видит» на странице
npx tsx scripts/mock-run.ts                 # прогон цикла со скриптованной моделью
npm run typecheck
```

### Настройки (.env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AGENT_MODEL` | `claude-opus-5` | основная модель |
| `SUBAGENT_MODEL` | `claude-sonnet-5` | субагент и компакция |
| `AGENT_EFFORT` | `high` | глубина рассуждений (`low`…`max`); `medium` заметно быстрее для демо |
| `MAX_STEPS` | `80` | шагов до запроса подтверждения |
| `CONTEXT_TOKEN_LIMIT` | `150000` | порог компакции |
| `BROWSER_CHANNEL` | `chrome` | `chrome` или `chromium` |
| `USER_DATA_DIR` | `.browser-profile` | профиль браузера |
| `RECORD_VIDEO` | `0` | запись видео |
| `VERBOSE` | — | `1` — показывать результаты инструментов целиком |

## Видео

Для демонстрации удобно поставить окно браузера и терминал рядом и записать экран (OBS, Xbox Game Bar `Win+G`, QuickTime). Флаг `--record` дополнительно сохраняет «чистое» видео браузера через Playwright.

## Ограничения и что дальше

- Содержимое cross-origin `<iframe>` (например, платёжные формы) в снапшот не попадает — только `click_at` по скриншоту.
- Капчи и анти-бот проверки агент не обходит; в таком случае он спросит пользователя.
- Возможные улучшения: серверная компакция и context editing из API Anthropic (не считаются правкой истории), параллельные субагенты для сравнения нескольких страниц, MCP-обёртка над инструментами браузера, чтобы подключать агента к другим клиентам.
